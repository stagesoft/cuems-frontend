## 5. `Media.duration` — the second site moved; the fix advice stands

`03` §3 and `04` §2 name `project-edit/sequence/sequence.component.html:134` as an interpolation of
`Media?.duration`. On `origin/main` (`22ce4c1`, `4f0256b`) that line is `{{ getCueMediaDuration(cue) }}`,
and the method (`sequence.component.ts:1248-1257`) returns
`cue.selectedMediaFile?.file?.duration || this.getCueData(cue.originalData)?.Media?.duration || '-'`.
The first operand is a string from `file_list`. The second is the wrapped object, so `[object Object]`
still shows whenever no file is selected. The fix site is `:1256`, not the template.

New since the bundle: `:1046` (`44bf807`) **writes** `Media.duration` back as a bare string from
`file_list`. The editor accepts that (`from_json` takes a bare timecode) and overwrites every media
duration from its database on save anyway, so this is not a blocker. Wrap it for symmetry, or leave it
and say why.

## 7. The descriptor, measured — Q2's capability exists but is not wire-shaped

`00` §3, §5 Q1, `02` C5 and `03` §2c ask to *confirm* that the descriptor's constructible empty instance
covers `getTemplateOutputStructure` before relying on it. Measured through
`ConfigManager.get_schema_descriptor(SchemaName.SCRIPT)`, which the editor serves as
`schema_descriptor`:

| Question | Answer |
|---|---|
| `master_vol` default | **100** (`script:AudioCueType`), as `03` §2a says. Still three `\|\| 20` sites |
| `dmx_channels` default | **`None`** (`script:DmxUniverseType`), as `03` §2b says |
| `opacity` default | 100 (`script:VideoCueType`) — delta (d) |
| per-type instance for audio/video outputs | **exists**: `script:AudioCueOutputsType`, `script:VideoCueOutputsType` (with `output_geometry`, `corners`, `canvas_region`) |
| …in the shape a cue on the wire has? | **No.** Instance: `{"output_name": null, "output_vol": null, "channels": {"channel": [{…}]}, "class": "audio"}`. Wire (`to_wire()` of a real cue): `{"CueOutput": {"output_name": …, "output_vol": 100, "channels": [{"channel": {…}}], "class": "audio"}}` — no `CueOutput` wrapper, `channels` nested the other way round, and every scalar `null` |

So cloning the instance where `getTemplateOutputStructure` cloned the template output yields a
structure the editor's save would reject. Per the bundle's own rule this is **an upstream report to
cuems-utils, not a local seed**: the instance should be in `to_wire()` shape (or the library should
publish the projection). Record it before planning; it decides `00` §5 Q1.

Also measured: the editor renders each type's `key` as `"script:AudioCueOutputsType"` (schema-qualified),
and field enums as their values.

**`config_save`** (`00` §3 "the remaining three config domains become editable", exit 6): the editor
refuses `script`, `hardware_outputs` and non-schemas, and answers `settings`, `network_map`,
`project_mappings` and `project_settings` with an error. `cuemsutils` has no public JSON ingestion for
config documents yet (cuems-editor `specs/001-cuems-utils-migration/upstream-reports/UR-5`). Exit
criterion 6 is therefore **blocked upstream**; record it as *not performed* with that reason. Adoption
is unaffected: it stays `nodelist_modify`.
